    Editorial & campaign calendar

    Method. Seasonal index = month average ÷ overall average × 100, over all years of monthly data. A month is a real peak at index ≥ 115 with the bump present in ≥ 60% of years; 107–115 is a mild bump; elevated months that only appear in a minority of years are inconsistent (usually one viral year). Ramp start = the week the 5-year average weekly curve crosses halfway from baseline (25th percentile) to peak. Lead-time rules: publish SEO content 8–12 weeks before ramp start; start paid 2–4 weeks before peak; cut spend the week after the peak breaks.
    Budget model. Each month gets a weight of (seasonal index ÷ 100) raised to the concentration exponent, so peaks pull budget super-proportionally. That weight is then shifted to buy ahead of demand: paid spend in a month serves that month and the next (50/50), content spend serves demand three months later. The two envelopes are normalized separately, blended by your content/paid split, and rounded to whole dollars summing exactly to the budget. It allocates a fixed budget across the year — it does not forecast revenue or ROI.
    Data. Google Trends is a relative index (0–100) within each query — never search volume. Terms downloaded in separate exports are not comparable to each other. Files live in data/, named <category>--monthly.csv / <category>--weekly.csv; rebuild with py analysis/build_site_data.py, or use Import above (browser-only, saved locally).

    Import a Google Trends CSV

    Export from trends.google.com/trends/explore → “Interest over time” → ⬇. Use 2004–present or a 10+ year custom range for the monthly file and Past 5 years for the weekly file. Granularity is auto-detected.

    Getting the data

    1. Go to trends.google.com/trends/explore.
    2. Enter one search term (use “search term”, not “topic”). Region: United States.
    3. Set time to 2004–present (or any 10+ year range) → download CSV → import here as the monthly file.
    4. Set time to Past 5 years → download CSV → import as the weekly file.
    5. Repeat per term. Or save files into data/ as births--monthly.csv etc. and run py analysis/build_site_data.py.

    Trends numbers are a relative 0–100 index within each query, not search volume.
